LokuOnX M11「出力とエフェクト」 完成予定の仕様 ＋ 現在の内部仕様(簡潔版)
作成: 2026-11-09 (M10) / 状態: 計画のみ(未実装) / 元資料: LokuOn リポジトリ docs/ の DECISIONS-summary・SUMMARY-additions

====================================================================
0. 前提(いちばん大事な点)
====================================================================
 ・添付の2つの仕様書は、別リポジトリ「LokuOn」(ghghuser/LokuOn。段階1〜6が実装済み・自己テスト310件)のもの。
   LokuOnX(M9まで完了)にはまだ何も入っていない。M11 = 「LokuOnで作った出力・ルーティング・エフェクトを、LokuOnXへ作り直して取り込む」。
 ・LokuOn の Core は OS非依存(名前空間 LokuOn.Core)。LokuOnX の Core は名前空間 Recorder.Core。コードはほぼそのまま移せるが、
   録音の内部構造が違う(5章)ので「そのまま差し込む」ことはできない。画面(WPF)は、LokuOnXのテーマ(ライト/ダーク/ニューモーフィズム)に合わせて作り直す。
 ・LokuOnX は net8.0-windows・NAudio 2.2.1(LokuOn の App は net9)。NAudio 3 への移行はしない(LokuOnの調査結果どおり)。

====================================================================
1. 完成予定の仕様(LokuOnの決定事項をLokuOnXの用語に直したもの)
====================================================================
[目的・原則]
 ・録音がメイン。ミックスした音を再生デバイス(スピーカー・ヘッドホン・VB-CABLE等)へ出す「出力」を追加機能として足す。
 ・使い方は 録音のみ / 出力のみ / 録音+出力。録音と出力は独立したスイッチ。
 ・出力側のトラブル(デバイスを抜く・開けない)で録音を止めない。出力が無効のときは追加の処理をしない(既存の録音・OFF時の動作は今のまま)。
[画面]
 ・出力ウィンドウ: 別ウィンドウ。メイン画面の⚙の左のアイコン(🔊)から開く。大きさ・位置を記憶。閉じても出力は止まらない。
 ・「出力ごとのカード」。最大4枚(最初は1枚「ミックス1」。「出力を追加」で増やし、4枚で追加ボタンは消える)。カードの枚数はプリセットに保存。
   カード = 名前(12文字まで)/ 出力先デバイス / 状態 / FX / ✕ / 「出力する」/ 全体音量 / メーター / エラー / 入力の一覧(チェック+音量。手動で畳める。畳みは出力ごとに記憶)。
 ・新カードの出力先は「未選択」で停止から始める。カード削除は確認ダイアログ(既定=いいえ)。狭いときはカードを折り返す(横スクロールにしない)。
 ・文字12px前後・余白10px前後・入力の行の高さ30px(コンパクト)。ウィンドウを開く前に暗い「読み込み中」を出し、デバイス一覧は別スレッドで取得(10秒キャッシュ)。
 ・メイン画面とトレイに「🔊 出力中」を表示。🔊クリックでメニュー(出力ごとのオン/オフ・すべて停止・すべて再開・出力ウィンドウを開く)、ダブルクリックで出力ウィンドウ(メニューは0.3秒待ってから出す)。
 ・簡単モニター(メイン画面のスイッチ1つ)は「再検討候補」＝M11では作らない。代わりに「ヘッドホン宛の出力カード」を使う。
[名前]
 ・入力・出力とも自由に名前を付けられ、プリセットに保存。既定=入力1〜4/ミックス1〜4。メイン画面の入力の名前(ダブルクリック/右クリック)・出力カード・エフェクトの見出しで共通に使う。
 ・LokuOnXの入力デバイス欄には今「入力N」のラベルが無いので、行の見出しとして足す(欄は増やさない)。
[音の流れと音量]
 入力 → 入力ごとのエフェクト → (録音へ:「録音に反映」がオンのときだけエフェクト後)
                           → 出力ごとの送り(オンオフ・dB) → 出力ごとのミックス → 全体音量 → 出力ごとのエフェクト → ±1に切り詰め → 再生デバイス
 ・入力ごとに「録音に反映」(既定オフ=録音は素の音)/「出力に反映」(既定オン)。音量は3段階: 入力ごと(既存−30〜+20dB)/入力×出力ごと/出力ごとの全体。
 ・無音分割・自動録音開始・各メーターの判定は、エフェクト前の音(Dry)で行う。「録音に反映」オンのときだけ、全体波形・出力レベルもエフェクト後。
[出力先・入力]
 ・送れるのは再生デバイスのみ。取り込み元と同じデバイスは出力先に選べない(ループ防止。🔊ループバック入力の元デバイス、既定への追従も含めて判定)。
 ・出力ごとの時計ズレは、バッファ＋±0.5%のリサンプラ調整(PI制御)で補正。目標たまり50ms、遅延の目安30〜110ms。足りなければ無音、250ms超は捨てる。
 ・Bluetooth等: デバイスのMixFormat(共有モードの形式)のまま開く(16/24/32bit整数・floatに対応)。開けなければ方式とバッファ長を変えて最大5通り再試行。失敗時は5秒ごとに自動再試行。
 ・アプリごとの音の分離は、アプリごとに別の仮想デバイスへ出力し、そのループバックを入力にする(Windows 11のアプリ別出力設定)。
[エフェクト]
 ・入力ごと: ノイズゲート → ローカット → グラフィックEQ(10バンド±12dB) → パラメトリックEQ(4バンド) → エコー → リバーブ(Freeverb)。
 ・出力ごと: ローカット → グラフィックEQ → パラメトリックEQ → リミッター(1.5ms先読み、上限-24〜0dB・既定-1dB)。専用ウィンドウ。
 ・パネルは1枚だけ開き、上の入力切替で移る。開き方=メーターのダブルクリック/FXボタン/右クリック。設定のコピー・貼り付け(反映先は貼らない)・すべてバイパス。
 ・VSTは保留(別プロセスのヘルパーexe方式が必要で大がかり。調査は LokuOn docs/INVESTIGATION-vst.txt)。
[プリセット・保存]
 ・出力先・送り・出力FX・入力FX・「録音に反映/出力に反映」・名前・出力カード枚数をプリセットに含める。旧プリセットは項目が無ければ「かけない/既定」で読む。
 ・iniとプリセットJSONの両方。範囲外・壊れた値は読み込み時に範囲内へ直す(Normalize)。初期値のままの項目はiniに書かない。プリセット切替時は動作中の出力を止める。
 ・LokuOnXのM5の規則は維持(保存先・番号はプリセットに入れない)。

2. 追加・取り込みの対象(LokuOn → LokuOnX)
====================================================================
 そのまま移せる(名前空間の変更のみ): Effects.cs(EffectSetting/EffectChain/ParamBand/EqBands/EqMath)、OutputFx.cs(OutputFxSetting/Limiter/OutputFxChain)、Routing.cs(MixBus。ビット一致テスト済み)。
 少し手を入れて移す: OutputRenderer(SourceBuffer・Trim付きリサンプラに依存)、OutputDevice(NAudio WASAPI出力。float配列の落とし穴あり→作業用配列で解決済み)、SourceBuffer(タップ付きリング)、
   LokuOnの StreamResampler(Trim付き)＝LokuOnXの同名クラスとは別物なので別名で取り込む(例 TrimResampler)、DeviceCatalog.IsLoopCombination。
 作り直す(LokuOnXのテーマ・部品に合わせる): 出力ウィンドウ・カード・FXウィンドウ(EffectWindow/OutputFxWindow)・GraphicEqControl・メーター(LokuOnXの LevelBar/GainMeter/LevelScale を使う)。
 テスト: LokuOnXには自己テストが無い。tests/ に自己テスト(コンソール)を作り、LokuOn側の該当テスト(Routing/Effects/Gate/Output/OutputFx)を移して Actions で実行する。

4. M10で決定した事項(2026-11-09。ユーザー回答)
====================================================================
 A. 出力の入力の取り方 = A2: LokuOnと同じく、入力(デバイス)を開いたままにして、出力用のタップ(複製バッファ)を取る。ASIOも出力に使える。
    → 録音の開始・終了で入力を閉じて開き直さない仕組み(LokuOnの SourceReuse 相当。条件: 枠・デバイス・周波数・チャンネルが同じ、かつすべて接続中)が必要。
      LokuOnで「録音開始・終了で出力が約0.5秒途切れる」不具合が出た部分なので、最初から作り込む(LokuOn SUMMARY 4b参照)。
      録音の開始時: 取り込み用バッファをClear(録音前にたまった古い音を録音の先頭に混ぜない)。出力のタップには触れない。
      LokuOnXでは、入力は DeviceInput/DeviceStream(MixedSource の下)、録音外では LevelMonitor が別に開いている。入力の持ち主を1つにまとめる設計が11-1〜11-2の最大の仕事。
 B. 入力名のラベル: 小さく、各入力デバイスのプルダウンの上に置く(メイン画面・出力カード・エフェクト見出しで共通の名前)。
 C. 簡単モニター: M11では作らない(ヘッドホン宛の出力カードで代用)。
 D. 別ファイル録音時のFX: 推奨案のとおり(「録音に反映」は各デバイスの音にそのまま掛かる)。
 E. プリセット適用時は動作中の出力を止める。将来、「止めない」オプションを足すかもしれない(M11では作らない。設定は出力停止を既定にして、後から足せる形にしておく)。
 F. 波形は今のまま(M10では変更しない)。

5. 現在の内部仕様(LokuOnX M9時点。M11が触る・避ける場所)
====================================================================
[構成] src/Core(OS非依存。名前空間 Recorder.Core)・src/Core/Win(NAudio・Win32)・src/UI(WPF・コードビハインド中心)。net8.0-windows、自己完結の単一exe、NAudio 2.2.1、FFmpegはビルド時に同梱。約130ファイル/約2万行。テスト用プロジェクトは無い。
[録音の音の流れ(float PCM)]
 デバイス(WasapiSource / AsioSource。IAudioSource) → DeviceInput(つなぐ・外れたら1秒ごとに再接続・既定に追従) → DeviceStream.Push
   = PcmConvert でfloat化 → ApplyGainAndPeak(ゲイン−30〜+20dB・滑らか・L/Rピーク) → 必要ならStreamResampler(周波数変換＋壁時計ずれの±0.1%伸縮) → FloatRing(時間軸)
 MixedSource(20msごとのタイマー): 壁時計より0.2秒遅れで各DeviceStreamの MixInto を足し、全体ゲイン→±1に切り詰め→DataAvailable。共通周波数=選んだデバイスの最大、チャンネルは1台ならそのまま・複数は最大ステレオ。
 RecordingGroup: ミックス=RecordingSession1つ / 別ファイル=デバイスごとに1つ(各々が1台のMixedSource)。分割・一時停止・停止は全セッション同時。
 RecordingSession: SilenceFiller(大きな欠落のみ無音補填。分割境界はフレーム単位)→FfmpegEncoder(専用スレッド+上限付きキュー、標準入力へPCM)。分割は次のFFmpegを先に起動して切替(途切れなし)。
   一時停止=デバイスは開いたまま音を捨てる(前後20msフェード)。仮名 _rec_* で書き、閉じた後に最終名へ(FileFinalizer。m4a整形・wav復旧)。異常終了時は起動時に Recovery。
 メーター・波形: DeviceStream.TakePeakLR / MixedSource.TakeDevicePeakPairs / RecordingSession.TakePeak・TakeChannelPeaks・TakeWave(0.04秒の最小/最大。BigWave・個別波形)。UIは50msのDispatcherTimerで読む。
 録音していないとき: LevelMonitor が選んだデバイスを開いてピークだけ測る(インジケーター(常時)・待機・自動録音開始)。録音・待機の開始前に手放す。
 判定: SilenceDetector(無音分割)・自動開始はピーク(ミックス後)を50msで見る。
[設定] Settings(ini。一時ファイル→置換。2つ目の起動は書かない)＋Settings.*.cs。入力は Device/Gain/Enabled(2台目以降は Device2…)、SeparateFiles。PresetData/PresetJson(Presets\名前.json、1件ずつ。保存先・番号は含めない)。入力は最大4(InputSetting(Key,GainDb,Enabled))。
[UI] MainWindow(.Recording/.Start/.Tray/.Auto)、DeviceList(入力4行+波形+GainMeter(L/R)+LevelScale)、OutputMeter、BigWave、PresetBar、FileListPanel+PlayerPanel(FFmpeg atempo)、SettingsWindow(⚙。ASIO・トレイ・ホットキー等)、TrayIcon(Shell_NotifyIcon・LedIcon)、ThemeManager(auto/light/dark/ニューモーフィズム2種)。
[M11への影響]
 ・DeviceStream.Push は ApplyGainAndPeak の直後が「エフェクトを掛ける位置」(「録音に反映」用。ピーク・無音判定のDryは掛ける前に測る)。録音のスレッド・ロックの中なので軽く作る。
 ・MixedSource の0.2秒遅れ・壁時計方式は出力には使えない(遅延が大きい)。出力は出力デバイスのコールバックで引く方式(LokuOnの OutputRenderer)が必要。
 ・LokuOnXは既に「待機・入力チェック」で録音外にデバイスを開く(LevelMonitor)。A2では入力の持ち主を1つにまとめ、録音・待機・出力が同じ入力を共有する(開き直さない)。
 ・ASIOは専有・1行のみ。A2ではASIOの入力も出力に送れる(タップ方式)。
 ・UIの追加場所: ⚙の左に🔊、DeviceListの各行にFXとメーターのダブルクリック、トレイの状態表示。ホットキー・予約・分割は録音側のまま。
 ・Linux移植の規則(Coreは WPF/Windows API に依存しない)を守る: OutputDevice と WASAPI出力は Core/Win に置く。
[ビルド] GitHub Actions(windows-latest)。Linuxでは Core のみビルド・テスト可(WPFは不可)。docs/・*.md・*.txt だけの変更ではビルドしない。成果物は直近2件。

6. 11-2 で確定・実装したこと（2026-11-10。詳細は PROJECT.md §3-9 と §11）
====================================================================
 ・入力の持ち主 = InputHub（参照カウント）。録音(MixedSource)・レベル表示(LevelMonitor)・出力(OutputEngine)が同じ入力を Acquire/Release で共有。
   録音の開始 = DeviceStream.Attach（ringを空にする＝古い音を混ぜない）、終了 = Detach。出力用のタップは触らない＝途切れない。
 ・出力に届く音 = 入力ゲイン後・デバイス本来の周波数・最大2ch（InputTap.Buffer。形式が変わると DeviceStream が作り直す）。
 ・OutputRenderer = 出力デバイスのコールバックで引く。バッファ目標50ms、±0.5%のPI制御、足りなければ無音、250ms超は捨てる。
 ・「出力する」は保存しない（起動のたびオフ）。出力先・音量は保存、プリセットには含めない（11-3）。
 ・ループ防止 = OutputGuard.IsLoop（出力先 = 入力の🔊と同じデバイス、「既定」も実デバイスで判定）。
 ・出力側の失敗は5秒ごとの再試行。録音は止めない。
 ・自己テスト: OutputTests / HubTests / EngineTests（tests/SelfTest。偽デバイスは Fakes.cs、Settings の定数は Stubs.cs）。
